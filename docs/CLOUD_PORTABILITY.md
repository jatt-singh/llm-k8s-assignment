# Cloud portability note

This is a written note only, not implemented. Each local component is mapped to its managed-cloud equivalent, with what would change. AWS is the primary target; GCP is shown for comparison. The Kubernetes layer (Helm chart, NetworkPolicies, PSS, HPA, PDB, CronJob, PrometheusRules) is cloud-neutral and ships unchanged. The changes are in Terraform providers and in a few chart values.

| Concern | Local (this repo) | AWS | GCP | What changes |
|---|---|---|---|---|
| **Cluster** | Kind via `tehcyx/kind` provider, one cluster per env | EKS (`terraform-aws-modules/eks`), managed node groups | GKE (private cluster, VPC-native) | Replace `modules/kind-cluster` with an EKS/GKE module, which also needs a VPC, private subnets and NAT. Providers authenticate with `aws eks get-token` / `gke-gcloud-auth-plugin` instead of client certs. The LLM gets its own CPU-optimised node pool (c7i / c3) with a taint. |
| **Registry** | `kind load docker-image` (no registry) | ECR, immutable tags, scan on push | Artifact Registry | `release` pushes to ECR and Helm references `repo@sha256:digest` instead of a tag. Nodes pull through an IAM node role or private endpoint. Image signing becomes enforceable (see below). |
| **Image signing** | Documented only (no registry to hold signatures) | cosign with a KMS key (`awskms://`), signatures stored in ECR | cosign + Cloud KMS, or Binary Authorization | CI runs `cosign sign --key awskms:///alias/llmstack-signing <digest>`. Admission control (Kyverno `verifyImages` or Sigstore policy-controller) rejects unsigned images in `llm-app`. |
| **Secrets** | `kubernetes_secret_v1` generated by Terraform (value in local, git-ignored state) | AWS Secrets Manager + External Secrets Operator, IRSA / EKS Pod Identity | Secret Manager + ESO, Workload Identity | Terraform creates the secret *container* only; values are set out of band. An `ExternalSecret` syncs `llm-api-key` and the incident webhook into the namespace. The chart is unchanged because it already reads from Secrets by name. etcd encryption with a KMS key. |
| **Ingress / TLS** | Traefik on a hostPort, self-signed cert from the `tls` provider, Traefik `ipAllowList` | AWS Load Balancer Controller (ALB) + ACM cert, or NLB + Traefik; WAF | GCLB via Gateway API + Google-managed cert; Cloud Armor | Real DNS (Route 53 / Cloud DNS) and a CA-issued cert (ACM, or cert-manager + Let's Encrypt). The IP restriction moves to the LB: `alb.ingress.kubernetes.io/inbound-cidrs`, security groups, or WAF / Cloud Armor. `externalTrafficPolicy: Local` preserves client IPs. The `ingress` namespace can then run PSS *restricted* (no hostPort). |
| **Storage (model)** | `local-path` PVC (RWO, node-local), filled by a download Job | EBS gp3 (RWO) per replica, **or** EFS (RWX) shared by all LLM replicas; or S3 + init-container sync | PD / Filestore, or GCS FUSE | With more than one LLM replica across nodes, use RWX (EFS/Filestore) or a per-pod download from an internal mirror (S3/GCS bucket with versioning + object lock). Hugging Face is then only touched by the mirror job. |
| **Logging** | Alloy → Loki (single binary, filesystem) | CloudWatch Logs via Fluent Bit (or keep Loki on S3) | Cloud Logging (built in) | Swap the Alloy `loki.write` endpoint for CloudWatch, or keep Loki with S3/GCS object storage and SimpleScalable mode. The JSON log format is unchanged. |
| **Metrics / alerts** | kube-prometheus-stack in cluster | Amazon Managed Prometheus + Managed Grafana, or keep the stack | Managed Service for Prometheus | PrometheusRules are portable. Alertmanager receivers point at Slack/PagerDuty with the webhook URL from Secrets Manager. |
| **Terraform state** | Local file per env (`state/<env>.tfstate`) | S3 bucket (versioned, KMS-encrypted) + native S3 lockfile, one key per env | GCS bucket with versioning | Only `envs/<env>.backend.hcl` changes. In practice also a separate AWS account / GCP project per environment. |
| **Network policy** | kindnet's built-in NetworkPolicy support | VPC CNI with network policy enabled, or Cilium | GKE Dataplane V2 | No manifest changes. The `model-download` egress could be narrowed further with FQDN policies (Cilium) or an egress proxy. |
| **CI/CD** | `scripts/ci.sh` on a laptop | Any runner (GitHub Actions, GitLab, Jenkins) calling the same script, with OIDC to assume a deploy role | Same, with Workload Identity Federation | No long-lived cloud keys in CI. Production apply is gated behind a manual approval on the runner. |

## What would *not* change

- Service code, Dockerfiles and the vulnerability gate.
- The Helm chart: security contexts, probes, NetworkPolicies, HPA/PDB, CronJob, alert rules.
- The model pinning and checksum verification logic.
